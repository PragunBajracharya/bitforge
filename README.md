## How the password protection works

There is no server and no Vercel middleware or Vercel password feature. Instead the **content itself is encrypted**:

1. `tools/protect.mjs` bundles every page, style and script in `source/`, compresses it, and encrypts it with **AES-256-GCM** using a key derived from your password (**PBKDF2-SHA256, 600,000 iterations**, random salt).
2. It writes `public/`, which contains only a login screen, the ciphertext (`app.enc`), the app icons and an offline cache worker.
3. In the browser, the login screen derives the key from the password you type and decrypts the app. A wrong password simply fails to decrypt.

So the deployed files are unreadable without the password. Anyone can download `app.enc`, but they cannot read it, and a long password makes guessing impractical. “Keep me signed in on this device” stores the derived key in that browser only; **Lock** (in the course menu) forgets it.

**Choose a strong password**: at least 10 characters; four or five random words are ideal. Changing the password and redeploying makes every saved login ask again.

> Only `public/` is meant to be public. `source/` is the readable app: deploy from a **private** GitHub repository, or use the CLI option below, which uploads only `public/`.

## Folder structure

```
bitforge/
├── package.json                # npm scripts: build, check, dev, preview (no dependencies)
├── vercel.json                 # Vercel: build command, output folder = public/, headers
├── tools/
│   ├── protect.mjs             # builds the encrypted public/ from source/ (needs BITFORGE_PASSWORD)
│   └── check-content.js        # content schema check
├── source/                     # the readable app (never deployed as is)
│   ├── index.html              # page shell; loads CSS and scripts in order
│   ├── manifest.webmanifest    # app name, icons, colors for installing on phones
│   ├── favicon.svg, icons/
│   ├── css/                    # base, components, courses, mobile
│   └── js/
│       ├── content/            # algorithms, crypto, system-design, data-analytics,
│       │                       # interview-prep, reference, depth, problems
│       └── core/               # topic engine, runner, lessons, problems UI, practice, app shell, mobile/PWA
└── public/                     # generated by protect.mjs: index.html (login), app.enc, sw.js, icons
```

## Deploy to Vercel

**Option A: GitHub (private repository)**

1. Push this folder to a **private** GitHub repository.
2. In Vercel: **Add New… → Project → Import** the repository. Framework preset: **Other**. Leave the build settings as they are; `vercel.json` already sets the build command (`node tools/protect.mjs`) and the output folder (`public`).
3. Before deploying, open **Settings → Environment Variables** and add `BITFORGE_PASSWORD` with your password (Production and Preview).
4. Deploy. If the variable is missing, the build stops with a clear message instead of publishing anything unprotected.

To change the password later, edit the variable and click **Redeploy**.

**Option B: from your computer (only the encrypted files are uploaded)**

```bash
cd bitforge
BITFORGE_PASSWORD='four random words here' node tools/protect.mjs   # Windows PowerShell: $env:BITFORGE_PASSWORD='…'; node tools/protect.mjs
cd public
npx vercel --prod
```

## Run locally

```bash
npx serve source        # the unprotected app, for editing
node tools/protect.mjs "a test password" && npx serve public   # the protected build
```

The login screen needs HTTPS or `localhost` (browsers only allow Web Crypto there).

## Install it as an app

After deploying (HTTPS is required):

- **Android (Chrome):** open the site and sign in, then tap **Install app** in the course menu, or Chrome's menu → **Install app**.
- **iPhone / iPad (Safari):** tap **Share** → **Add to Home Screen**.
- **Desktop (Chrome, Edge):** click the install icon in the address bar.

The installed app opens full screen and works offline after the first visit (the service worker caches the encrypted bundle; it is decrypted on your device each time).

## External resources

Loaded from public CDNs at runtime: Google Fonts; highlight.js 11.9.0 (cdnjs); sql.js 1.10.3 (cdnjs, only in the SQL playground); Pyodide 0.26.4 (jsDelivr, only when you run Python on a problem page, about 10 MB once).

## Saving progress

Progress, your code, notes and review schedule are stored in the browser with `localStorage`; nothing is sent to a server. Use **Export progress** / **Import progress** in the course menu to move them between devices. Every unit, topic and problem has its own link (e.g. `/#/problems/146`).

## Checking content

```bash
node tools/check-content.js
```

## Adding a course

1. Add topic files under `source/js/content/<course>/` and include them in `source/index.html` before `js/core/app-shell.js`.
2. In `app-shell.js`, add the course to `COURSES`, `TRACK_INFO`, `UNITS` and `TRACKS`.
3. Add a color token in `source/css/base.css` for light and dark themes, then rebuild with `tools/protect.mjs`.
